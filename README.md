# AirWatch — บอร์ดเดียว ตั้งค่าครั้งเดียว

ESP32 อ่านเซนเซอร์และควบคุมพัดลมเอง หน้าเว็บแสดงค่าล่าสุด กราฟ ประวัติ และสถานะพัดลม โดยใช้หน้าตาเทาดำ/เขียว/ฟ้าแบบเดิม

รุ่นนี้ไม่ต้องเพิ่มอุปกรณ์หรือเลือกบอร์ดในเว็บ Server เตรียมบอร์ดให้อัตโนมัติและคงรหัสเดิมถ้ามีอยู่แล้ว สิทธิ์ยังจำกัดเจ้าของเดิมและผู้ดูแล ไม่เปิดประวัติส่วนตัวให้ผู้สมัครทั่วไป การดู/เปลี่ยนรหัสเชื่อมต่อทำได้เฉพาะ admin

## ใช้กับ Laragon

1. ติดตั้ง Node.js **22 ขึ้นไป** และเปิด MySQL ใน Laragon
2. ดับเบิลคลิก `Start-AirWatch.cmd` ครั้งแรกตัวช่วยจะถามข้อมูลฐานข้อมูลและบัญชีผู้ดูแล ไม่ต้องแก้ไฟล์โค้ด
3. เปิด http://localhost:3000 และเข้าสู่ระบบด้วยบัญชีผู้ดูแลเดิม (ถ้ามี) หรือบัญชีที่ตั้งในตัวช่วย
4. เปิดเมนู **ผู้ดูแลระบบ → รหัสเชื่อมต่อบอร์ด** แล้วคัดลอกรหัสตั้งค่า
5. ตั้งค่า ESP32 ตามหัวข้อด้านล่าง

เปิดใช้งานครั้งถัดไป: เปิด Laragon แล้วดับเบิลคลิกไฟล์เดิม ค่า JWT/ฐานข้อมูลเก็บใน `.env` นอก git ไม่สุ่มใหม่ทุกครั้ง เก็บไฟล์นี้เป็นความลับและสำรองไว้ ตัวช่วยไม่เขียนทับบัญชีหรือไฟล์ตั้งค่าเดิม

Node server จะรัน migration ก่อนเริ่มทุกครั้ง รันซ้ำได้และรักษาชนิด FLOAT/DECIMAL กับข้อมูลเดิม ถ้ามีอุปกรณ์เดิมหลายตัว ตัวช่วยจะถามว่าจะใช้ตัวใด โดยไม่ลบอุปกรณ์หรือประวัติอื่น

หากต้องการรันด้วย Terminal: `npm ci` → `npm run configure` → `npm start`

## ตั้งค่า ESP32 ครั้งแรก

ใช้ ESP32 Dev Module (ESP32 รุ่นคลาสสิกที่มีปุ่ม BOOT บน GPIO0) โปรแกรมรองรับ pin ของบอร์ดนี้ตามตารางด้านล่าง บอร์ดรุ่นอื่นต้องตรวจ pin ก่อนใช้งาน

1. อัปโหลด firmware รุ่นนี้ผ่าน Arduino IDE ครั้งแรก โดยวาง `firmware.ino`, `sensor_filter.h`, `connection_config.h` และ `tls_roots.h` ในโฟลเดอร์ sketch เดียวกัน ไม่ต้องแก้ IP, Wi-Fi หรือรหัสในไฟล์
2. ใช้ ESP32 board package **3.0.7**, WiFiManager **2.0.17**, Adafruit AHTX0 **2.0.6**, SparkFun Indoor Air Quality Sensor - ENS160 **1.1.0**, PMS Library **1.1.0** (dependencies ติดตั้งตาม Library Manager)
3. เชื่อมมือถือกับ Wi-Fi **AirWatch-Setup** และเปิดหน้าตั้งค่า เลือก Wi-Fi 2.4 GHz ของสถานที่พร้อมรหัสผ่าน
4. วาง **รหัสตั้งค่าบอร์ด** ที่คัดลอกจากเว็บลงในช่อง **Connection code** แล้วบันทึก
5. บอร์ดจำค่าใน NVS และเชื่อมใหม่อัตโนมัติทุกครั้งที่เปิดไฟ

ต้องการเปลี่ยน Wi-Fi หรือย้ายเซิร์ฟเวอร์: ขณะบอร์ดทำงานให้กด BOOT ค้างอย่างน้อย 3 วินาทีแล้วปล่อย บอร์ดจะ restart เข้าหน้าตั้งค่าอีกครั้ง ไม่ต้องแก้โค้ดหรือล้าง Flash (อย่ากด BOOT ค้างขณะเปิดไฟ เพราะบางบอร์ดจะเข้าโหมดอัปโหลด)

หน้า portal มีเวลา 180 วินาที ตั้งไม่ทันให้กด BOOT ใหม่ ระหว่าง restart/setup พัดลมหยุดตามขั้นตอนเริ่มต้น แล้วกลับไปควบคุมเองหลัง setup/warm-up

## การเชื่อมต่อสองแบบ

- เปิดเว็บผ่าน HTTP ใน LAN: รหัสขึ้นต้น `AUTO|...` บอร์ดค้นหา server ผ่าน UDP โดยไม่ต้องกรอก IP ใช้เครือข่ายที่เชื่อถือได้ เปิด firewall TCP 3000 และ UDP 41234 เฉพาะ LAN; Wi-Fi ต้องไม่บล็อก broadcast/client isolation
- เปิดเว็บผ่าน HTTPS บนโดเมนจริง: รหัสรวม URL ของโดเมนและ key ไว้แล้ว บอร์ดใช้ DNS + HTTPS ตรวจใบรับรองด้วย ISRG Root X1/X2 และเวลา NTP ไม่ใช้ `setInsecure()` และไม่เปลี่ยนกลับไป HTTP/discovery เมื่อ TLS ล้มเหลว

หากเปลี่ยน IP ของเซิร์ฟเวอร์แต่ใช้โดเมนเดิม ให้แก้ DNS ที่ผู้ให้บริการ โค้ดบนบอร์ดไม่ต้องเปลี่ยน หากเปลี่ยนโดเมน ให้คัดลอกรหัสตั้งค่าใหม่จากเว็บแล้ววางใน portal

รหัสตั้งค่ามี secret สำหรับส่งข้อมูล อย่าโพสต์หรือส่งภาพรหัสในที่สาธารณะ หากรั่วให้กดเปลี่ยนรหัสแล้วตั้งบอร์ดใหม่

## Deploy เป็นเว็บจริง

มี Docker Compose สำหรับ **Linux server/VPS + โดเมนที่ชี้มาที่ server** ประกอบด้วย Node.js, MySQL และ Caddy HTTPS ข้อมูล DB/ใบรับรองเก็บใน persistent volumes

บน server ที่ติดตั้ง Docker Compose และ Node.js 22 แล้ว:

```sh
npm ci
npm run configure:cloud
docker compose --env-file .env.cloud up -d --build
```

ตัวช่วยถามโดเมนและบัญชีผู้ดูแล แล้วสร้าง JWT/password ของฐานข้อมูลให้เอง ไม่ต้องแก้ source code เปิด TCP 80/443 ที่ server และตั้ง DNS A/AAAA ให้ถูกต้องก่อนเริ่ม Caddy ขอและต่ออายุใบรับรอง Let's Encrypt อัตโนมัติ ไม่เปิดพอร์ตฐานข้อมูลออก Internet

หลังเปิดเว็บ `https://โดเมนของคุณ` ได้ ให้คัดลอกรหัสตั้งค่าจากเว็บนั้นไปวางใน ESP32 ตอนนี้สามารถปิดคอม/Laragon ที่บ้านได้ เพราะ server บนคลาวด์ทำงานแทน แต่บอร์ดต้องมีไฟและอินเทอร์เน็ต

ชุดนี้ใช้ Let's Encrypt ให้ตรงกับ trust anchors ของ firmware หากใช้ reverse proxy/CDN/โฮสติ้งอื่นที่ออกใบรับรองจาก CA คนละชุด ต้องตรวจความเข้ากันได้ก่อนใช้ ไม่ถือว่าทุกผู้ให้บริการรองรับโดยอัตโนมัติ

รายละเอียด DNS, อัปเดต, สำรอง และตรวจรับ: [DEPLOYMENT.md](DEPLOYMENT.md)

## อุปกรณ์และพฤติกรรม

| อุปกรณ์ | Pin |
| --- | --- |
| PMS ในบ้าน | RX16 / TX17 |
| AHT10/20, ENS160 | SDA21 / SCL22 |
| MQ-2 ในบ้าน | GPIO34 |
| รีเลย์พัดลมระบาย / กรอง (active-low) | GPIO25 / GPIO26 |
| เซนเซอร์นอกบ้าน (ตัวเลือก) | PMS RX4/TX5, MQ-2 GPIO35 |

ค่าเริ่มต้นเป็นพัดลมเดียว: PM >35 เปิดระบาย, PM <30 ปิด, ช่วง 30–35 คงสถานะ; ข้อมูล PM หายคงสถานะล่าสุด มี warm-up 30 วินาทีและเว้นการสลับรีเลย์อย่างน้อย 5 วินาที

เซนเซอร์/พัดลมนอกบ้านยังปิดเป็นค่าเริ่มต้น การเปลี่ยนฮาร์ดแวร์ไปเป็นสองพัดลมยังต้องเลือก firmware build ที่ตรงกับฮาร์ดแวร์ ไม่เกี่ยวกับการเปลี่ยน Wi-Fi/IP

eCO₂ เป็นค่าประมาณของ ENS160, MQ-2 เป็น ADC ดิบ ตัวกรอง EMA เก็บทศนิยมและรีเซ็ตหลัง PMS ขาดข้อมูล ไม่ใช้ค่า AQI ที่แปลงแบบสมมติ

พัดลมควบคุมบนบอร์ด ไม่ขึ้นกับการเปิดหน้าเว็บ แต่การส่ง HTTP/TLS เป็น synchronous จึงต้องวัดความหน่วงขณะเครือข่ายล่มกับบอร์ดจริง

## ข้อมูลและการทดสอบ

API อ่านข้อมูลต้องล็อกอินและตรวจสิทธิ์บอร์ดเดียวที่ตั้งไว้: `/api/device`, `/api/latest`, `/api/history`, `/api/history/daily` บัญชีใหม่ไม่ได้สิทธิ์อ่านบอร์ดเก่าโดยอัตโนมัติ API เพิ่ม/claim หลายอุปกรณ์ถูกถอดออก

`POST /api/log` ใช้ `X-Device-Key`; JSON fields: in_pm, in_co2, in_gas, out_pm, out_gas, vent, filt, temp, humidity ใช้ NULL สำหรับเซนเซอร์ที่ขาดและ 0 สำหรับค่าศูนย์จริง ห้ามเปิดพัดลมทั้งสองพร้อมกัน

ประวัติที่ยังไม่มี device_id เก็บไว้โดยไม่เดาเจ้าของ Server ลบข้อมูลอายุมากกว่า 30 วันตามนโยบายเดิม จึงควรสำรองก่อนอัปเดตหากต้องการเก็บประวัตินานกว่านั้น

`npm test` ตรวจ API, สิทธิ์, Socket.IO, DOM, migration, provisioning และ compile/run ตัวกรองกับตัวแยกรหัส C++ โดยไม่ต้องมีบอร์ด CI เพิ่ม MySQL จริง, Docker build, Caddy config และ Arduino firmware compilation พร้อมไฟล์ artifact

ผล compile/tests ไม่แทนการทดสอบ Wi-Fi, TLS กับโดเมนจริง, sensor/relay และขนาดหน้าจอใน browser ดู [UPGRADE_GUIDE.md](UPGRADE_GUIDE.md)
